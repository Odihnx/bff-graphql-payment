## Project Overview

ODIHNX GraphQL Payment BFF — a Backend for Frontend (BFF) service built in Go that exposes a GraphQL API for payment flow and locker booking operations. It sits behind APISIX Gateway and communicates downstream via gRPC with Payment Manager and Booking Manager microservices.

## Commands

### Run locally
```bash
go run cmd/server/main.go
# or use the dev script (Windows):
scripts/run_dev.bat
```

### Build
```bash
go build ./cmd/server/...
docker build -t bff-graphql-payment .
docker-compose up
```

### Dependencies
```bash
go mod tidy
```

### Generate GraphQL code (after schema changes)
```bash
go run github.com/99designs/gqlgen generate
```

### Generate gRPC stubs from Buf registry (requires `buf` CLI + `BUF_TOKEN`)

buf generate buf.build/odihnx-prod/service-booking-manager --template buf.gen.booking.yaml

## Architecture

The project follows **Clean Architecture + Hexagonal Architecture** with strict layer boundaries:

```
Domain (no external deps)
  internal/domain/model/        - PaymentInfra entity
  internal/domain/ports/        - Use-case interfaces
  internal/domain/service/      - Domain logic
  internal/domain/exception/    - Domain errors

Application (use cases)
  internal/application/service/ - PaymentInfraService (orchestrates domain)
  internal/application/ports/   - Repository/outbound interfaces
  internal/application/exception/

Infrastructure (adapters)
  Inbound:
    internal/infrastructure/inbound/graphql/resolver/   - gqlgen resolvers (query/mutation/subscription)
    internal/infrastructure/inbound/graphql/mapper/     - DTO ↔ domain model conversions
    internal/infrastructure/inbound/graphql/dto/        - Request/response DTOs
    internal/infrastructure/inbound/graphql/errors/     - GraphQL error formatting with HTTP extensions
    internal/infrastructure/inbound/middleware/         - auth_middleware.go (JWT header extraction), http_status_middleware.go

  Middleware (cross-cutting):
    internal/infrastructure/middleware/service_validation_middleware.go
      → Called before every GraphQL operation; queries APISIX Control Gateway to verify the service is not disabled/in-maintenance

  Outbound:
    internal/infrastructure/outbound/gateway/    - APISIX Control Gateway HTTP client + in-memory cache (TTL_CONTROL_CACHE)
    internal/infrastructure/outbound/grpc/client/ - Payment & Booking Manager gRPC clients (real + mock)
    internal/infrastructure/outbound/grpc/mapper/ - Proto ↔ domain mappers

config/    - DI container (NewContainer) and lifecycle/graceful-shutdown (NewLifecycle)
cmd/server/main.go - Entry point: wires middleware stack, starts HTTP server on PORT (default 8080)
graph/schema.graphqls          - Source of truth for the GraphQL schema (edit here, then regenerate)
graph/generated/generated.go   - Do not edit; regenerated by gqlgen
graph/model/models_gen.go      - Do not edit; regenerated by gqlgen
```

## Key Architectural Decisions

**Mock vs Real services:** When `ENV=development` or `USE_MOCK=true`, `config/container.go` wires mock gRPC clients (`*_mock.go`) instead of real ones. No code changes needed to switch modes.

**Service validation middleware:** Every GraphQL resolver invokes `ServiceValidationMiddleware` before executing. It calls `POST /validate/service` on the APISIX Control Gateway with `{"service_name": "payment"}`. Results are cached in memory for `TTL_CONTROL_CACHE` seconds (default 300).

**Authentication:** APISIX Gateway validates JWTs before requests reach this service and injects headers (`X-Auth-Validated`, `X-User-ID`, `X-User-Email`, `X-JWT-Claims`). `auth_middleware.go` extracts these into the request context. GraphQL directives (`@auth`, `@hasRole(role: "SUPER_ADMIN")`) enforce authorization at the resolver level.

**Error HTTP status codes:** `HTTPStatusMiddleware` wraps the response writer and reads the `httpStatus` extension field from GraphQL errors to promote the correct HTTP status code (e.g., 401, 403, 503) instead of always returning 200.

**gRPC stubs:** Generated Go code lives in `gen/go/proto/` and is committed to the repo. Re-generate only when upstream proto definitions change in the Buf registry.

## Environment Variables

| Variable | Default | Purpose |
|---|---|---|
| `ENV` | `development` | Switches mock/real mode |
| `PORT` | `8080` | HTTP listen port |
| `HOST_API_PAYMENT` / `PORT_API_PAYMENT` | `localhost` / `50051` | Payment Manager gRPC |
| `HOST_API_BOOKING` / `PORT_API_BOOKING` | `localhost` / `50052` | Booking Manager gRPC |
| `HOST_GATEWAY_CONTROL` / `PORT_GATEWAY_CONTROL` | `localhost` / `9081` | APISIX Control Gateway |
| `CONTROL_SERVICE_NAME` | `payment` | Service name sent to Control Gateway |
| `TTL_CONTROL_CACHE` | `300` | Control Gateway cache TTL (seconds) |
| `USE_MOCK` | `true` in dev | Force mock clients |

Copy `.env.example` to `.env` for local development.
